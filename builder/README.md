# Builder 方案

## 方案概述

本方案通过统一聚合与视图投影构建 Dashboard 分组结果。`DashboardBuilder` 先按集群和每台服务器的最高优先级服务类型完成分组及排序，`GetDashboard` 返回嵌套视图；`GetFlatDashboard` 则复用嵌套结果，将服务分组投影到固定的 AS、TS、SS、DS 字段及 `no_service` 独立列表。因此两种输出共享同一套聚合规则和强类型返回值，避免分别实现两套分组流程。没有服务的服务器进入 `NoServiceType` 分组，不会从 Dashboard 结果中丢失。

此处的 Builder 是负责组装结果的服务，并非具有分步配置过程的经典 GoF Builder 模式。方案适合分组规则统一、输出结构固定的场景；若分组键和组间排序需按业务规则灵活切换，可比较 rule 方案。当前分类规则只将服务器归入其最高优先级类型，不等同于按完整服务组合分组。

## 架构与设计模式

本包采用统一聚合核心与视图投影的结构：`DashboardBuilder.GetDashboard` 执行集群与服务类型聚合、排序；`GetFlatDashboard` 复用该结果，再转换为固定的平铺 DTO。这种方式集中维护核心分组规则，并通过明确的返回类型区分视图，避免策略入口使用 `any`。

`DashboardBuilder` 在这里是组织结果构建流程的服务，不是经典 GoF Builder 模式；它没有逐步配置产品的过程。此架构适用于聚合语义相同、仅输出形状不同的视图。若不同页面的分组键或分类规则本身不同，应显式建模规则，而不是只增加投影字段；若服务类型组合需要完整区分或支持 SS/DS 合并规则变化，应扩展分类语义，不能直接依赖“最高优先级服务类型”这一现有归组规则。

## 可维护性与演进性分析

- **新增输出视图：**新增强类型结果结构和投影方法，复用 `GetDashboard` 的聚合结果；当视图只改变字段布局时，修改范围较小，核心聚合仍保持单一来源。
- **调整分组或分类规则：**主要修改 `GetDashboard` 中的归组规则及相关优先级/比较辅助函数；所有视图会共享该行为，降低规则漂移，但也意味着不同视图无法独立选择不同分组键，除非进一步显式引入分类规则。
- **新增排序算法：**修改或增加排序比较函数，并在统一聚合流程中使用；目前没有 `Sorter` 注入点，若调用方需要运行时替换排序方式，需要扩展 Builder 的依赖。
- **新增服务类型：**需更新服务类型优先级和比较逻辑，并为 `ClusterFlatGroup` 增加对应字段及 `GetFlatDashboard` 的转换分支；服务类型与平铺 DTO 耦合。
- **新增分组规则：**当前没有规则表或规则参数入口；不同分组键若仅作为另一个视图处理，需新增分组流程或抽取可复用的分类核心。若业务规则会持续变化，应考虑将分类决策显式建模，而不是不断扩展条件分支。
- **修改共同执行流程：**嵌套聚合集中在 `GetDashboard`；平铺视图复用其结果。对共同聚合和排序的改动通常只需维护一处，体现单一职责与避免重复的收益。
- **调整外部规则参数或序列化：**本包没有规则参数解析层；调用方通过选择具体方法决定视图。JSON 契约由结果类型的字段和标签定义，新增或重命名字段时需同步校验输出。

总体而言，该方案对“相同业务分组、不同响应形状”的演进较友好；若演进重点变成多种服务组合分类、可配置组间顺序或 SS/DS 合并规则，应先扩展规则模型再投影视图。
